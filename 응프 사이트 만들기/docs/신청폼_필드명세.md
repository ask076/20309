# 신청 폼 필드 명세서

**이 명세는 모든 팀 공통입니다. 항목을 추가하거나 빼지 마세요.**  
5주차에 이 항목들로 테스트 케이스를 만들기 때문에, 팀마다 다르면 테스트를 진행할 수 없습니다.

---

## 항목 7가지

| # | 항목 | id / name | type | 필수 | 검증 규칙 |
|---|---|---|---|---|---|
| 1 | 이름 | `name` | `text` | ● | 비어 있으면 안 됨 |
| 2 | 연락처 | `tel` | `tel` | ● | `010-0000-0000` 형식 |
| 3 | 이메일 | `email` | `email` | ● | 이메일 형식 |
| 4 | 참가 인원 | `count` | `number` | ● | 1 이상 4 이하 |
| 5 | 희망 좌석 | `seat` | `radio` | ● | 앞열 / 중앙 / 뒷열 중 하나 |
| 6 | 요청 사항 | `note` | `textarea` | — | 없음 (선택 입력) |
| 7 | 개인정보 동의 | `agree` | `checkbox` | ● | 체크해야 함 |

> 라디오(5번)는 `id`가 아니라 `name="seat"`으로 묶습니다. 같은 `name`을 가진 것끼리 하나만 선택됩니다.

---

## 항목별 상세

### 1. 이름
```html
<input type="text" id="name" name="name" required
       placeholder="홍길동" autocomplete="name">
```
- 오류 문구: `이름을 입력해 주세요.`

### 2. 연락처
```html
<input type="tel" id="tel" name="tel" required
       pattern="010-\d{4}-\d{4}"
       placeholder="010-1234-5678" autocomplete="tel">
```
- 안내 문구(hint): `하이픈(-)을 포함해 010-0000-0000 형식으로 입력합니다.`
- 오류 문구: `010-1234-5678 형식으로 입력해 주세요.`

`pattern` 읽는 법
- `010-` — 이 글자 그대로
- `\d` — 숫자 하나
- `{4}` — 바로 앞의 것을 네 번 반복

### 3. 이메일
```html
<input type="email" id="email" name="email" required
       placeholder="hong@example.com" autocomplete="email">
```
- 오류 문구: `이메일 주소 형식을 확인해 주세요.`
- `type="email"`만 써도 브라우저가 `@` 포함 여부를 검사합니다. `pattern`은 필요 없습니다.

### 4. 참가 인원
```html
<input type="number" id="count" name="count" required
       min="1" max="4" value="1">
```
- 안내 문구: `1회 신청당 최대 4명까지 가능합니다.`
- 오류 문구: `1명 이상 4명 이하로 입력해 주세요.`

### 5. 희망 좌석
```html
<div class="radio-group">
  <label><input type="radio" name="seat" value="앞열" required> 앞열</label>
  <label><input type="radio" name="seat" value="중앙"> 중앙</label>
  <label><input type="radio" name="seat" value="뒷열"> 뒷열</label>
</div>
```
- 오류 문구: `희망 좌석을 선택해 주세요.`
- `required`는 그룹 중 **하나에만** 붙이면 됩니다.

### 6. 요청 사항
```html
<textarea id="note" name="note"
          placeholder="휠체어 이용, 단체 신청 등 알려주실 내용을 적어주세요."></textarea>
```
- 선택 입력이므로 `required`도 오류 문구도 없습니다.
- `<textarea>`는 `<input>`과 달리 여는 태그와 닫는 태그가 따로 있습니다. 사이에 아무것도 쓰지 마세요.

### 7. 개인정보 동의
```html
<label class="agree" for="agree">
  <input type="checkbox" id="agree" name="agree" required>
  <span>신청 확인을 위해 이름과 연락처를 수집하는 데 동의합니다.
        수집한 정보는 행사 다음 날 삭제됩니다.</span>
</label>
```
- 오류 문구: `개인정보 수집에 동의해야 신청할 수 있습니다.`
- 다른 항목과 달리 `<label>`이 `<input>`을 **감싸고** 있습니다. 이렇게 하면 글자를 클릭해도 체크됩니다.

## 오류 메시지 위치

각 항목마다 아래 문단을 넣어두세요. 평소에는 CSS가 숨기고, 5주차에 JS가 보이게 만듭니다.

```html
<p class="error" id="err-name">이름을 입력해 주세요.</p>
```

`id`는 `err-` 뒤에 항목 이름을 붙입니다.

| 항목 | 오류 문단 id |
|---|---|
| 이름 | `err-name` |
| 연락처 | `err-tel` |
| 이메일 | `err-email` |
| 참가 인원 | `err-count` |
| 희망 좌석 | `err-seat` |
| 개인정보 동의 | `err-agree` |

## 5주차 테스트를 위한 참고

이 명세가 곧 테스트의 기준입니다. 예를 들어 참가 인원은 `1 이상 4 이하`이므로 다음 네 가지를 넣어봐야 합니다.

| 입력값 | 기대 결과 |
|---|---|
| 0 | 거부 |
| 1 | 통과 |
| 4 | 통과 |
| 5 | 거부 |

경계 바로 안쪽과 바로 바깥쪽을 함께 보는 것을 **경계값 분석**이라고 합니다.

연락처처럼 형식이 정해진 항목은 성질이 같은 것끼리 묶어 대표 하나씩만 넣어봅니다. 이것을 **동등 분할**이라고 합니다.

| 입력값 | 성질 | 기대 결과 |
|---|---|---|
| `010-1234-5678` | 올바른 형식 | 통과 |
| `01012345678` | 하이픈 없음 | 거부 |
| `010-123-5678` | 자릿수 부족 | 거부 |
| (비움) | 미입력 | 거부 |

나머지 항목의 테스트 케이스는 5주차 3차시에 직접 만듭니다.
